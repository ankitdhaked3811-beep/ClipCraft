## 2026-11-04 - Caching Video Metadata Extraction & Query Minimization
**Learning:** In video downloading/processing services using `yt-dlp`, calls to `extract_info` require remote network requests and HTML/JSON parsing on streaming websites (e.g. YouTube), taking between 500ms to 2500ms per request. Furthermore, URLs containing playlist query parameters (e.g., `&list=...`) cause yt-dlp by default to fetch and parse entries for the entire playlist even when only a single clip is requested.
**Action:** When extracting metadata in web endpoints, always specify `'noplaylist': True` in `ydl_opts` unless explicit playlist functionality is required, and use a thread-safe bounded in-memory LRU+TTL cache keyed by video URL. Cache hits drop lookup latency from ~1-2 seconds to ~0.001ms (>99.9% reduction) while safeguarding worker thread capacity.
